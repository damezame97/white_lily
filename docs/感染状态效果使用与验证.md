# 感染状态效果：实现、调试与验证

环境：Minecraft 1.20.1 / Forge 47.4.10 / Java 17；核对的 ISS 为 1.20.1-3.16.3，TaCZ 为 1.1.8-hotfix。

## 规则及扩展位置

Java 目录：`src/main/java/com/damezame97/white_lily/`。

- `white_lilybuff/mob_effects.java`：复用唯一效果注册入口；`infection_effect.java` 为所有新效果提供 Forge 治疗物品空表。牛奶无法治愈这些效果，不拦截喝奶行为，也不修改原版失明/中毒的治疗能力。普通效果移除 API 和命令仍工作。
- `infection/infection_symptom_rules.java`：固定条件、事件持续时间、感知周期、随机池、属性修正及统一 `strength(Player)`。目前强度恒为 **1.0**。作者现有意志属性为 `white_lily:willpower_strength`（意志坚韧，默认0.05）；没有把它与 SAN 视作同一属性，也没有另注册“意志坚定值”。
- 所有负面属性减值、间隔延长、回复量减值、移动增幅、额外魔力成本和失明持续时间经过同一个强度入口。概率、阈值、冷却、事件持续时长及健康正面加成不经过该入口。
- `infection/infection_service.java`：原感染积累公式和1200刻被动周期保持不变。成功的外来/被动**实际增量**才调用 `onIncrease`。管理 set/add/reduce、加载、上限截断为零不触发随机池。
- `infection_service.treat(player, amount)`：明确的主动治疗入口，返回真正降低量。原 `reduce` 保持管理/直接降低语义。新增权限2测试命令 `treat` 使用主动治疗入口，不添加医疗品。
- 随机池：`registerRandom(ResourceLocation, duration)` 等权登记本模组已注册效果。当前只有寒颤、施术失稳；概率为80～149.9的10%、150～229.9的20%、230～300的30%。抽取后不论成功失败冷却600刻；已有同名不刷新、不重抽。新增效果需要一起登记实际属性行为和语言。
- `infection/infection_symptoms.java`：原统一重评入口仍保留，先重评本次规则，再执行未来额外 Java 规则。玩家 END tick 每刻重评，但只在变化时添加/移除效果或修改属性。
- `infection/infection_modifiers.java`：固定规则 ID+属性生成稳定 UUID；只操作所属修饰符。用于感染积累的耐力取值排除本框架自己的耐力修正，保留 SAN 和装备修正，按全部三种属性操作完整计算。

## 伤害、回复与移动消耗

- 普通伤害先经过护甲、抗性、吸收生命，再进入 `LivingDamageEvent`。项目固定/百分比减伤为 NORMAL；载重增幅改为 LOW，明确先于戒指的 LOWEST。戒指处理函数在拆分70%/30%及合并旧延期欠款前，向感染框架传入本次应承受的完整生命伤害。
- 分类入口是 `infection/infection_damage.java`。普通近战/蜂刺/箭矢/三叉戟使用可扩展标签 `data/white_lily/tags/damage_type/infection_direct_hit.json`；TaCZ 使用实际 `BULLETS_TAG`。
- 已核对 `SmallMagicFireball.onHitEntity` 使用 `BLAZE_STORM_SPELL` 的直接命中，所以接入“烈焰风暴小火球+对应法术 ID”的组合判断。`registerSpell(id, predicate)` 供后续已核实法术接入。没有把全部 ISS 法术都当作直接伤害；火球范围爆炸、其他未核实法术暂不触发渗血。燃烧、中毒、延期及追罚通过显式排除标签/分类排除；单凭攻击者存在不能通过判断。
- 只改 `RECOVERY_INTERVAL` 和 `RESTORE_HEALTH`，不拦截所有 `LivingHealEvent`。渗血不削弱其他模组直接 `heal` 或原版治疗药水。间隔三症状可加算至50秒，现有回血计时不重置，仍遵守5秒下限；无饱和度分支完全保留。
- `infection/infection_recovery.java` 协调 SAN 与渗血的回复量下限：SAN 读取时排除自身与感染扣减；感染只扣 SAN 后剩余非负量。考虑装备乘法修正，不拆装真实属性，不抹去原本为负的回复量。SAN 原有阈值、惩罚请求量和计时规则保持不变。
- `gamerule/hunger_activity.java` 只在移动的基础每米消耗上乘增幅。呼吸急促+恢复疲劳为 `1+0.25+0.10=1.35`；走路、攻击、挖掘和独立跳跃消耗不受改动。不另扣饥饿值或原版疲劳。

## ISS 成本与感染性失明

经用户允许，新增两个独立 Mixin；作者原有 Mixin Java 文件没有修改。

- `mixin/infection/MixinInfectionSpellCost.java`：核对 ISS 3.16.3 的 `AbstractSpell.getManaCost(int)`、`canBeCastedBy`、`castSpell`。当前版本没有可供该需求直接使用的玩家减耗属性；`getManaCost` 已包含该法术配置的 `MANA_MULTIPLIER`，在其结果上加15%。单靠 `SpellOnCastEvent` 只能改扣费，无法同时改预检查，因此没有使用“再额外扣一次魔力”的做法。
- 预检查与实际构造扣费事件时共用 `infection_mana.cost`；客户端公共成本显示也调用该入口。客户端实现隔离在 `client/infection_mana_display.java`，并区分客户端线程与集成服务器线程，避免借用房主给别的玩家算成本。
- 保留 ISS 的 `CastSource.consumesMana()`、创造模式与 recast 等原有扣费开关。自动测试实际调用了普通火球的 `canBeCastedBy` 和 `castSpell`，核对魔力不足及单次扣除。未声称所有附属模组、覆盖公共成本方法的法术或特殊施法方式均兼容。其他模组仅在 `SpellOnCastEvent` 中改最终费用的行为，本来就没有对应公共预检查/显示接口，仍需按具体模组进一步协调。
- `mixin/client/MixinInfectionBlindness.java`：感染性失明是独立 MobEffect。只让原版 `FogRenderer.BlindnessFogFunction` 按当前摄像实体选择感染实例或更长的外部失明实例。没有给玩家加原版 BLINDNESS，也没有修改/缩短/清除外部实例。复用的是原版失明雾与变暗路径；没有新增屏幕特效。
- 命令移除感染性失明、死亡或框架禁用不会凭空产生清明。发作自然结束时只在服务端时钟产生一次清明。清明期间命中下一感知周期会跳过该次失明并重启周期，不补发。

## 保存、开关、同步与显示

- 事件时钟保存在现有 `infection_state` 的 `symptoms` 子字段，由 `infection_symptom_state` 验证边界；包括事件效果剩余时间、随机池冷却及感知周期。旧档缺字段默认0，异常非有限值归零。
- 离线暂停，换维度保留，非死亡复制使用独立副本并保留同 tick 去重。死亡清空事件症状/计时；感染值按现有 `infection.keepOnDeath` 配置处理（默认true），复活重评固定条件。
- 现有 `infection.enabled` 默认true；关闭或创造/旁观/无敌模式暂停相关时钟并移除本系统效果及修正，重新启用按条件恢复。不会改变 Happy_mode 开关含义。
- 感染数据沿用原最小 S2C 通道；状态和属性使用原版/Forge 自带同步，不新增每刻时钟包、不刷聊天。
- `client/infection_effect_display.java` 提供1～12号不同颜色的占位图标，未生成或覆盖图片。背包中悬停这些状态图标可查看中英文客观说明（自动换行）。
- 将来正式图标可放入 `src/main/resources/assets/white_lily/textures/mob_effect/<注册名>.png`，例如 `healthy_condition.png`、`wound_seepage.png`、`infection_blindness.png`。推荐18×18透明PNG；存在时自动替代编号占位，无需模型 JSON。

## 调试步骤

以下命令需要权限2；用生存模式测试自动触发。当前感染没有自然来源，仍需模拟或管理命令起步。

```mcfunction
/white_lily infection get @s
/white_lily infection set @s 200
/attribute @s white_lily:san base set 4000
/white_lily infection simulate @s 1 10
/white_lily infection treat @s 30
/effect clear @s white_lily:wound_seepage
```

`set` 和 `reduce` 不触发随机池或疲劳；`simulate` 遵守来源及框架开关，只有实际增加才抽随机池；`treat` 是特意标记的主动治疗测试入口。

建议在测试存档中操作（SAN、属性命令会修改该存档玩家数据）：

1. 满血看体况良好；实际受伤后看解除；用普通治疗恢复满血看重新出现。
2. 感染设200、SAN设4000、生命降至70%以下，观察迟滞/急促/焦虑/涣散。SAN恰好5000时焦虑和涣散应解除。
3. 感染设30，比较裸身3点生命伤害、护甲或黄心吸收后不足3、戴戒指时拆分前3点的渗血表现；多次命中看最长60秒。
4. 感染设150、SAN设999，等待60秒；看3秒感染性失明后30秒清明。另加原版失明并喝牛奶，原版失明应可清除，感染效果应保留。
5. `treat @s 30` 查看疲劳；原感染20时请求治疗50不应疲劳。设高感染后重复 `simulate`，每次判定至少相隔30秒，检查两种随机症状共存。
6. 对同一种普通 ISS 法术比较涣散前后显示、魔力不足预检查与实际消耗；还需手动验证连续施法/卷轴/recast及使用中的具体附属装备。
7. 带随机症状或渗血退出重进、换维度、死亡重生，检查剩余时间与清理；切创造/旁观、关闭后开启框架检查暂停恢复。
8. 多人客户端与开服端都替换为同一份新JAR，检查状态图标、渲染与数据同步。

## 自动验证结果

自动测试为 `gametest/InfectionSymptomsGameTests.java`（13项，包含多组确定性断言），并更新两处旧感染测试夹具，避开新健康抗性及显式提供随机池随机数。

最终单独执行 `gradlew.bat build` 成功，日志 `build/infection-symptoms-build.log`。完整 GameTest **181项中180项通过，新增13项全部通过**，日志 `build/infection-symptoms-verification.log`。唯一失败为原有 `phantomFragmentsResourcesAreShipped`：原断言要求“幻像碎片”栏位翻译为空，作者当前资源有正式名称。本次没有修改这项旧资源规则；完整 GameTest 命令因此返回失败，不能声称全套通过。

同时核对了中英文12组名称与说明、Mixin配置、JAR中的新类与伤害标签，`git diff --check` 无空白错误。产物为 `build/libs/white_lily-0.1.2.jar`。

未实际进行启动器/IDEA多人连接、真实退出重进与维度旅行、客户端失明画面和状态图标人工检查。服务端测试包含纯保存/加载、独立克隆、时钟暂停恢复及实际 ISS 成本链路；不能将这些自动检查表述为全部游戏内兼容性验证。
