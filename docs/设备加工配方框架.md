# 设备加工配方框架：第一版

设备白名单决定机器会做什么，与玩家研究、机器owner分开。第一版接入普通熔炉、烟熏炉、高炉；不改变简易加工台、TaCZ或其他模组机器。

设备身份隔离现已实现：全局RecipeManager保留原始完整配方；已接入设备使用独立视图。原版适配同时核对方块注册ID与方块实体类型，其他模组仅共享SMELTING/SMOKING/BLASTING类型不会自动接入，也不会被清零加工进度。

## 默认分工

| 设备 | 允许的实际配方 |
|---|---|
| 普通熔炉 | 18条：7种肉/鱼、土豆、海带；玻璃、木炭、红砖、陶瓦、石头、平滑石、深板岩；仙人掌和海泡菜染料 |
| 烟熏炉 | 9条熟食：7种肉/鱼、土豆、海带；保留原有100刻配方速度 |
| 高炉 | 9条：铁/金/铜各自的普通矿石、深层矿石、粗矿；保留原有100刻速度 |

玻璃的原版配方接受沙子及红沙。装备回收、下界金矿、远古残骸、其他矿物、其他普通烧制均未列入；模组新配方也不会自动开放。

手动和漏斗都查询最终配方表；未允许的输入可以停留在槽内，但不加工、不消耗输入或新燃料。已点燃燃料仍按原版燃烧，不返还已用燃料；已有成品不删除。燃料种类未改。

## 新高炉制作与解锁

```text
石砖    石砖    石砖
石砖    熔炉    石砖
平滑石  煤炭块  平滑石
```

配方仍使用稳定ID `minecraft:blast_furnace`，材料5石砖+1熔炉+2平滑石+1煤炭块。首次获得熔炉解锁高炉制作，不要求铁锭；获得煤炭解锁 `minecraft:coal_block`。木炭不触发煤炭块路线，也不能替代配方中的煤炭块。

个人解锁表已删除33条旧烧制/烟熏/高炉授予规则：获得矿物、熟食原料、沙子、黏土或熔炉不再增加个人炉子加工权限。染料入口只授予合成类染料知识，绿染料和海泡菜烧制染料由熔炉白名单提供。旧玩家已有记录保留；手册节点、研究条件和简易加工台登记机制不改。

## 数据包规则

内置规则位于 `data/white_lily/machine_rules/furnace.json`、`smoker.json`、`blast_furnace.json`，随JAR生效。外部数据包用完全相同的命名空间和路径覆盖一台设备的完整规则文件；同路径由最高优先级数据包覆盖。不同路径若控制同一设备身份则报冲突；不同设备可以共享配方类型，各有独立规则。

```json
{
  "adapter": "white_lily:vanilla_cooking",
  "device": "minecraft:furnace",
  "mode": "whitelist",
  "allow": ["minecraft:cooked_beef", "minecraft:glass"],
  "deny": [],
  "copies": []
}
```

- `whitelist`：只允许allow及本文件copies创建的配方；空清单即禁用该设备全部加工。deny优先。
- `blacklist`：保留该设备类型的原有配方，再排除deny；不属于第一版默认配置。
- `allow`、`deny`使用具体配方ID，不是物品ID。白名单ID不存在或类型不符会报错。
- 新增配方可以正常写到 `data/<命名空间>/recipes/<名称>.json`，再把其ID加入对应白名单。
- 可选 `required_mod`：对应模组未安装时跳过此文件。可用适配器仍需由代码注册，JSON不能自动适配未知设备。
- 配方类型只用于寻找原始候选配方，不决定哪些机器受控。适配器必须显式实现matches，按设备身份接入；仅注册适配器或共享配方类型不会影响其他机器。支持同类型不同设备视图，暂不支持每台机器独立配置。

### 复制或迁移

在目标设备规则的copies中加入：

```json
{
  "source": "minecraft:glass",
  "id": "example:glass_in_blast_furnace",
  "cooking_time": 100,
  "remove_source": true
}
```

保留原料Ingredient、产物数量/NBT、经验、分组和分类；时间可覆盖，不填或0时继承源配方。目标ID必须唯一。复制只接受已核对的原版SmeltingRecipe/SmokingRecipe/BlastingRecipe具体类；不默默丢弃自定义配方子类的额外逻辑。源配方从完整全局表查找；复制产物仅存在于目标设备私有视图，不注入全局表。remove_source只从已接入设备视图移除源ID，不删除未接入机器使用的原始配方。

## 加载、重载和排错

规则在RecipeManager解析原始配方后生成设备私有视图；原版继续同步完整全局表，设备视图经独立的仅服务端到客户端通道同步。普通浏览器按个人设备获得历史揭示相应视图，不授予个人加工权限。管理员“显示所有”可以跳过查看权，但三个炉子的配方展示仍使用设备视图，不把全局炼矿配方误标为普通熔炉可做。受限制的工作台、四格和加工台配方按原规则展示。原始表替换和设备视图更新都会触发列表及指纹缓存刷新。

`/reload`重新读取规则。已接入炉子直接从对应设备视图选择匹配配方，并用同一结果计算加工时间，不会让一条全局禁用候选遮住后面的允许配方。运行期间视图版本变化后，下次接入机器tick清零加工进度、重算时间，不删除输入或成品。读档或区块重新加载后的首次tick仅建立版本基线：当前输入仍有允许配方且加工时长未变时保留已保存进度，否则清零；不恢复或复制燃料。未接入机器保持原版配方查找及进度。原始配方表被代码替换时也重建视图，已移除的配方不能继续执行。

解析、白名单校验、复制、ID冲突任一步失败，不发布半套迁移；已接入设备视图关闭，日志指出文件及原因，全局表和未接入设备不受影响。修好数据包并再次reload即可恢复；不会回退为全部开放。未安装模组的可选规则按required_mod跳过。

管理员权限等级2可查询：

```mcfunction
/white_lily_machine_rules
/white_lily_machine_rules minecraft:furnace minecraft:glass
/white_lily_machine_rules minecraft:furnace minecraft:iron_ingot_from_smelting_raw_iron
```

输出规则来源、模式、最终条数和指定配方是否存在于该设备最终表中。第一版查询支持上述三个原版设备。

核心类位于 `machine/`；`machine_adapter`是后续代码接入点。新工作方块仍需自己的方块、槽位、加工逻辑及适配；框架不自动生成机器，也不自动取消研究登记。

## 验证

自动测试覆盖严格表、实际加工速度、拒绝炼矿不吞料/新燃料、复制迁移的数据保留、错误策略和冲突、重载进度、缓存配方移除及无铁高炉路线。客户端浏览器重载表现和实际漏斗装置交互仍需玩家验证；不启动客户端。
