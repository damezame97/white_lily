# 配方图鉴与个人解锁

本模组自带客户端配方图鉴，不需要安装 JEI。背包、合成台和其他容器界面右侧显示玩家已解锁配方的产物；未解锁配方不进入搜索、用途查询和收藏结果。服务端验证合成权限，客户端的显示状态不授予权限。

## 金剑范例

创造模式中打开「配方书」标签页，取出「配方书-金剑」（`white_lily:golden_sword_recipe_book`）。金剑配方 `minecraft:golden_sword` 默认锁定，拾取金锭不会解锁金剑。主手或副手右键阅读后，仅使用者解锁原版金剑配方，已摆放的合成网格立即刷新。

生存模式首次学习消耗一本；重复阅读不消耗；创造模式保留书。数据包移除目标配方时不消耗书。范例贴图原样复制自本次用户提供的 PNG，保留其透明背景和像素。

## 个人进度

记录位于每个玩家自己的 playerdata NBT：`ForgeData.PlayerPersisted.white_lily_recipe_unlocks`，保存已授予的配方 ID、首次获得过的物品 ID 和修订号。登录、存读档、死亡重生、维度切换会保留个人进度；其他玩家、共用世界和共用工作台不授予个人知识。

现有调查手册和研究树继续生效。完成研究授予该节点绑定的配方；撤销研究后，有效制作权限随之撤回。机器内已有登记不能替代操作者本人的解锁和研究条件。

## 数据包配置

随模组提供的默认规则位于 `src/main/resources/data/white_lily/recipe_unlocks/defaults.json`。可在数据包的 `data/<namespace>/recipe_unlocks/*.json` 添加规则；同路径文件按原版资源包优先级覆盖。执行 `/reload` 后应用配置。

```json
{
  "initial": ["minecraft:crafting_table"],
  "initial_outputs": ["#minecraft:planks"],
  "on_pickup": [
    {
      "item": "minecraft:iron_ingot",
      "recipes": ["minecraft:iron_pickaxe"],
      "outputs": ["minecraft:bucket"]
    }
  ],
  "on_advancement": [
    {
      "advancement": "minecraft:story/mine_stone",
      "recipes": ["minecraft:stone_pickaxe"]
    }
  ]
}
```

`initial`、`recipes` 填配方 ID；`initial_outputs`、`outputs` 根据产物物品 ID 或 `#物品标签` 解析配方。`on_pickup.item` 支持物品 ID 或 `#物品标签`。这里的「首次获得」包括捡起掉落物、制作、熔炼和容器转入主背包；服务端周期检查补足其他模组没有发送拾取事件的转移。

普通原版配方通知和已知配方书残留不会自行解锁。扩展事件在服务端调用 `recipe_unlocks.unlock(ServerPlayer, ResourceLocation)`；禁止提供能让普通客户端任意提交解锁 ID 的网络入口。

没有原版配方 ID 的操作使用 `white_lily:operation/<operation>` 权限 ID，具体操作及支持范围见实现和验证记录。配方书类 `recipe_unlock_book` 接受固定配方 ID 列表，可用同一类注册后续配方书物品。

## 验证

`RecipeUnlockGameTests` 覆盖金剑初始锁定、手动摆料、过期结果、直接 Shift、原版自动填料、阅读与重复使用、双玩家隔离、真实玩家 NBT 存读、死亡及非死亡 Clone，以及创造栏和贴图资源。加工台、其他菜单和客户端验证结果在完工时追加。

构建：使用 Java 17 执行 `gradlew.bat build --offline`。完整服务端回归：`gradlew.bat runGameTestServer --offline`。已有测试失败须按实际日志报告，不能将编译成功等同于测试全部通过。
