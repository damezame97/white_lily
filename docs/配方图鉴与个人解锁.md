# 配方图鉴与个人解锁

本模组自带客户端配方图鉴，不需要安装 JEI。背包、合成台和其他容器界面右侧显示玩家已解锁配方的产物；普通模式下未解锁配方不进入搜索、用途查询和收藏结果。打开简易加工台时，浏览器还会临时加入该机器当前可执行的加工配方，范围只限这个菜单会话。服务端验证合成/填充权限，客户端的显示状态不授予权限。

管理员测试模式是例外：创造模式且拥有命令权限等级 2 的玩家可以主动打开“显示所有物品”，临时浏览未解锁物品和全部真实配方；退出该模式或离开服务器后恢复普通范围。该模式不改变个人研究、配方解锁、配方书记录或机器登记。

## 金剑范例

创造模式中打开「配方书」标签页，取出「配方书-金剑」（`white_lily:golden_sword_recipe_book`）。金剑配方 `minecraft:golden_sword` 默认锁定，拾取金锭不会解锁金剑。主手或副手右键阅读后，仅使用者解锁原版金剑配方，已摆放的合成网格立即刷新。

生存模式首次学习消耗一本；重复阅读不消耗；创造模式保留书。数据包移除目标配方时不消耗书。范例贴图原样复制自本次用户提供的 PNG，保留其透明背景和像素。

## 个人进度

记录位于每个玩家自己的 playerdata NBT：`ForgeData.PlayerPersisted.white_lily_recipe_unlocks`，保存已授予的配方 ID、首次获得过的物品 ID 和修订号。登录、存读档、死亡重生、维度切换会保留个人进度；其他玩家、共用世界和共用工作台不授予个人知识。

现有调查手册和研究树继续生效。完成研究授予该节点绑定的配方；撤销研究后，有效制作权限随之撤回。

简易加工台是例外：机器登记决定本机能加工什么，登记后的研究加工配方多人共享。个人研究只决定“能向机器登记什么”，不决定“能否使用已登记机器”。旧的 operator/outputOwner/outputRecipe 已废弃；加工台不再绑定当前操作者，也不会因登记者离线、死亡或换维度暂停。

熔炉系列只放开成品拿取：烧制仍看机器 owner 的权限，已烧好的结果任何正常菜单使用者都能取。

## 加工台机器上下文

打开简易加工台后，服务端把本机当前有效能力绑定到该 `processing_menu` 会话：基础加工配方 + 已登记且研究绑定有效的加工配方。客户端浏览器在这段时间内可浏览“个人已学 + 本机能力”，机器权限精确到配方 ID，不会展示同产物其他未解锁路线。

- 关闭菜单、切换机器、退出、方块移除或菜单失效后，机器额外权限立即清除。
- 新增登记后，所有正在查看该机器的玩家刷新。
- 详情区分“已掌握 · 本机可加工”“本机已登记 · 个人未研究”“本机未登记，请点击‘登记已学配方’”“基础加工 · 本机可用”。
- 填充请求仍由服务端重新验证菜单、方块实体、距离、配方 ID、登记状态、材料和库存；客户端上下文只用于显示和按钮状态。

## 作弊测试浏览与管理员给予

浏览器右下角“作弊设置”只有同时满足 **创造模式 + 命令权限等级 2** 时才可用；默认两个开关都关闭。单人世界使用真实作弊/命令权限，多人服务器使用请求者本人的权限，不会临时给玩家 OP 或提升权限等级。

- **物品拿取**：开启后，在右侧物品列表条目上左键给予 1 个，Shift+左键给予一组；数量由服务端读取当前 `ItemStack` 的真实最大堆叠数，不可堆叠物品为 1。客户端只发送“给予 1 个/一组”的已定义请求，服务端重新验证权限、物品、容器会话，并通过请求玩家自己的命令来源执行 `/give @s`。不改变真实背包槽位、鼠标携带栈或“＋”填充按钮。
- **显示所有物品**：列出注册物品、无配方物品，以及有限且合法的药水/喷溅药水/滞留药水/附魔书变体；不使用任意 NBT 组合。搜索、排序、收藏、分页、列表比例继续有效。
- 两个开关独立：只开显示所有物品时不会自动给物品；只开物品拿取时只从当前正常可见范围给予；两者都开时可浏览并给予未解锁物品。
- 给予不直接授予配方或研究；正常 `/give` 获得事件仍会触发既有的首次获得发现/解锁规则。所有实际合成、烧制、加工和填充仍按原权限检查。
- 退出服务器/世界、切换回生存或失去命令权限后，开关和作弊浏览范围立即清除。状态不写入个人研究或手册 NBT。
- 物品拿取开启时，Shift+左键优先给予一组，不再同时触发 Shift 收藏；左键也不再同时打开配方。改绑到不冲突按键的收藏仍正常，中键等原有不冲突入口保留。提示中的收藏键读取当前实际绑定。
- 网络使用独立频道 `white_lily:browser_cheat`；权限包只同步“可用/不可用”，给予包只含物品栈、1个/一组、请求号和当前 containerId；服务端拒绝旧菜单、空物品、空气和5刻内重复请求。

## 数据包配置

随模组提供的默认规则位于 `src/main/resources/data/white_lily/recipe_unlocks/defaults.json`。可在数据包的 `data/<namespace>/recipe_unlocks/*.json` 添加规则；同路径文件按原版资源包优先级覆盖。执行 `/reload` 后应用配置。

```json
{
  "initial": ["minecraft:crafting_table"],
  "initial_outputs": ["#minecraft:planks"],
  "on_pickup": [
    {
      "item": "minecraft:iron_ingot",
      "recipes": ["minecraft:iron_pickaxe"],
      "outputs": ["minecraft:bucket"]
    }
  ],
  "on_advancement": [
    {
      "advancement": "minecraft:story/mine_stone",
      "recipes": ["minecraft:stone_pickaxe"]
    }
  ]
}
```

`initial`、`recipes` 填配方 ID；`initial_outputs`、`outputs` 根据产物物品 ID 或 `#物品标签` 解析配方。`on_pickup.item` 支持物品 ID 或 `#物品标签`。这里的「首次获得」包括捡起掉落物、制作、熔炼和容器转入玩家背包（代码扫描 41 格，含盔甲栏和副手）；服务端周期检查补足其他模组没有发送拾取事件的转移。

普通原版配方通知和已知配方书残留不会自行解锁。扩展事件在服务端调用 `recipe_unlocks.unlock(ServerPlayer, ResourceLocation)`；禁止提供能让普通客户端任意提交解锁 ID 的网络入口。

没有原版配方 ID 的操作使用 `white_lily:operation/<operation>` 权限 ID，具体操作及支持范围见实现和验证记录。配方书类 `recipe_unlock_book` 接受固定配方 ID 列表，可用同一类注册后续配方书物品。

## 2026-10-24 浏览器优化：紧凑设备页与独立缩放

本节替代上文历史记录中“浏览器尚未接通按键/单条深色配方页”的说明。最终客户端实机效果统一 **待用户验证**。本次没有运行 `runClient`、Computer Use 或操作用户世界。

### 操作与布局

- 列表主体透明；仅顶部搜索/控制与底部页码保留半透明底色。实际控件与物品格接收事件，列表空白不拦截后方槽位；详情为模态界面，输入不穿透真实库存。
- 详情使用原生像素绘制的浅灰框、凹槽、灰箭头，不使用概念图作为整张背景。不新增装饰背包。图标与数量均来自真实配方。
- 顶部设备分类按钮循环当前查询实际有的分类；同分类真实配方按稳定配方ID顺序纵向排列。底部为查询返回、前后页、实际页码。每条配方各自的 `＋` 绑定它自己的配方ID。
- 有序配方保留宽高与空位，标准合成绘制九宫格；无序明确标记。烧制有原料/火焰/空燃料位/结果和时间经验，**没有固定煤炭消耗**。加工台独立显示工具、原料、容器、成品、返还和副产物；切石、锻造保留专用布局。特殊配方保留已有规则预览。
- 每条配方下方只常显一行紧凑元数据（有序/无序、权限来源、配方来源）；悬停该行可读完整规则、配方ID和全部备注。剪刀固定耐久返还、蜂蜜瓶与显字处方返瓶单独展示/说明；动态锻造结果不承诺固定继承数据。

### 两套比例与分页

客户端配置：`config/white_lily-recipe-browser.json`：

```json
{"sort":"DEFAULT","itemScale":100,"recipeScale":100}
```

两套比例分别为 **50%～150%，默认100%，每次增减10个百分点**。点击各自百分比恢复100%。列表缩放只改变格子步距/图标/数量，搜索、控制、页码仍保持正常GUI字号；配方缩放改变槽位、图标、数量、箭头及每条填充按钮，分类、提示和分页控制不跟着缩小。与原版GUI缩放、研究树缩放无关。

- 列表按实际可用宽高与缩放格距计算列、行和每页数量；模组标题保留可读高度。缩放/窗口变化尽量把之前第一页首项重新定位到新分页，NBT不同的变体不合并。
- 配方单元按实际设备图高度加一行紧凑元数据计高，完整单元逐条打包到页；Ingredient替代材料轮播不额外计为配方，也不为临时填充反馈预留大块空白。无结果时页码保持1/1。
- 缩放/窗口变化按当前配方ID重新定位；不总回第一页。太窄时临时降低实际图形比例，显示“首选比例→适配比例”，不改配置；极小窗口提示扩大窗口。确实超高的特殊规则卡单独成页并允许滚动，不把半条普通配方拼在正常页面底部。
- 右侧可用空间不足时减少列数，再自动收起为入口；不会用透明覆盖真实槽位补空间。自动收起与手动偏好分开。

### 排序、查询历史与按键

- 默认保留原浏览器按显示名不区分大小写的顺序，补充稳定ID/NBT平局规则。
- 名称模式按当前语言排序：中文使用Java17简体中文Collator，已用阿/八/陈/李/王/张/赵实际验证拼音次序；英文忽略基本大小写。多音字采用JDK排序表，不做词义分词推断。
- 模组分组按物品namespace；Minecraft在前，其余按实际模组显示名，无名称回退namespace；组内按名称。配方来源另行展示，不等同于产物所属模组。
- 排序结果在索引代次缓存，语言、资源/标签、个人权限和当前机器上下文变化后失效；不每帧全量排序。
- 查询历史属于当前浏览器/游戏会话，不绑定某一个配方详情Screen：关闭详情回到容器后仍保留，最多32条；仅真实目标/模式变化入栈，保存物品NBT、配方/用途、设备、配方ID、滚动位置和查询上下文。返回不会把刚离开的页面再次压入，也不会恢复过时的搜索/排序/缩放偏好；返回后按当前比例与权限重新定位配方页。退出世界或断开时清空。
- 返回时重新读取当前可见索引，不保存机器权限快照；配方失效显示友好提示。无效菜单/机器关闭时不继续持有临时权限。
- 已接入另一助手的KeyMapping桥接；默认Ctrl+O显示/隐藏，Ctrl+F搜索，R配方，U用途，A收藏，左右方向键翻页。可在原版按键设置修改；提示读取实际绑定。搜索输入期间不触发这些浏览器动作。没有保留重复的硬编码R/U/A判断。

### 权限与填充反馈

不改变服务端制作规则。基础加工、本机登记/个人未研究、个人掌握/本机未登记、个人掌握/本机可加工在详情备注区分。未研究者只在当前有效登记机器内获得该精确加工配方的临时浏览/填充权限，不获得个人研究，也不开放同产物其他路线。熔炉只延续既有取货放开，烧制门控未更改。

`＋`灰色时悬停显示真实客户端预判，服务端收到请求再次验证并返回可翻译结构化码：设备不匹配、不支持、未授权、本机未登记、缺原料、缺工具、缺容器、回收输入时背包满、槽位分配失败、菜单/距离/机器失效、配方数据变化、请求过快。缺材料不被统一归为未授权。

服务端沿用原子填充规划与原版合成摆放；请求带菜单、配方指纹和序号，重复包不再次消耗/转移。客户端在服务端真实返回 `OK` 后才关闭详情并回到原背包/工作台/加工台；失败留在详情并显示结构化原因，菜单失效安全退出，80tick 无回应则恢复按钮。旧响应按“菜单会话 + 请求号 + 配方ID”丢弃，不能关闭后来的详情页。现有不支持自动填充的烧制、切石、锻造/特殊配方只读预览，**本轮没有添加它们的服务端制作逻辑**。

网络频道 `white_lily:recipe_unlocks` 协议从1变为2；客户端和服务器需同时更新同一正式JAR。

### 前景弹层

- 作弊设置仍要求创造模式 + 命令权限等级2，两个开关含义未变；设置菜单不需要权限。
- 底层物品列表先绘制；作弊/设置菜单在 `Render.Post` 之后作为当前活动层绘制，背景不透明，最后绘制菜单自身提示。
- 菜单覆盖范围内的原生槽位tooltip被取消；底层物品不显示悬停高亮或物品提示。
- 点击菜单外只关闭菜单，并由面板拦截该次点击，不穿透到给予、收藏、配方/用途查询或真实背包槽位。
- 菜单按鼠标锚点避让屏幕边缘；底部空间不足时向上展开。窗口尺寸改变时由新的Screen初始化或布局检测关闭菜单。设置菜单与作弊菜单互斥。

### 右栏顶部与设置

- 第一行只保留标题、设置按钮、收起按钮；第二行是搜索框。物品列表从搜索框下方立即开始。
- 排序（默认/名称/模组分组）、物品列表比例加减和恢复100%、仅收藏开关移入设置菜单。
- 设置按钮悬停提示显示当前排序、物品比例和收藏筛选状态。
- 配方页面比例仍独立控制，不与物品比例合并；客户端配置 `white_lily-recipe-browser.json` 的保存键不变。

### 每页多条紧凑配方

- 配方单元高度 = 真实设备图高度 × 实际比例 + 一行元数据；不再为三行备注预留空间。
- 工作台单元为九宫格 → 产物 → 独立 `＋`，下方一行显示有序/无序、权限来源、配方来源；悬停该行显示完整备注和配方ID。
- 常规窗口、100%配方比例下，普通工作台配方每页至少3条；总配方不足3条时显示真实数量。小窗口减少每页条数，不重叠、不截断半条；真正超高的特殊卡单独成页并允许滚动。
- 每条 `＋` 保存并提交其实际配方ID，不从替代材料复制配方；缩小比例会增加每页条数，窗口/比例变化按当前配方ID重新定位。
- 加工台继续显示工具、容器、材料、成品、返还物、副产物；烧制保留燃料位、时间、经验；切石/锻造保留专用布局。临时“等待/失败原因”只占底部一行紧凑状态区。

### 填充返回

- 点击 `＋` 后进入短暂等待并禁用重复提交；只有收到匹配当前菜单会话、请求号、配方ID的真实 `OK` 回应，才关闭详情并返回原容器。
- 失败留在详情并显示具体原因；`MENU_INVALID` 安全退出，不返回失效菜单；80tick无回应恢复按钮。
- 关闭详情、成功返回或失败停留都不自动制作、不自动取成品，也不改变服务端原子填充权限。
- 复用原Screen和原containerMenu，不重新打开工作方块；返回后保留全局搜索、排序、物品比例、配方比例和有效查询历史。

### 会话历史与动态分类

- 历史保存在当前浏览器会话，不随详情Screen销毁；关闭详情→回容器→查询另一物品→“返回”可回到上一查询（例如丛林木板→关闭→书→返回丛林木板）。
- 仅真实目标/模式变化入栈，最多32条；返回不把刚离开页面再次压入，也不恢复过时搜索/排序/缩放偏好；退出世界/断线清空。
- 返回时按当前个人权限、当前机器上下文和作弊状态重新筛选；旧机器临时配方不会因历史恢复，失效目标显示提示。
- 设备分类继续只来自当前查询实际匹配的 `Display.category`；无匹配隐藏，单分类不显示切换箭头，多分类紧凑循环；查询/权限/机器/作弊变化后重算并纠正页码。

### 设备权限现状

- 熔炉/烟熏炉/高炉都属于`AbstractFurnaceBlockEntity`，`recipe_machine_owner`按机器登记的owner玩家调用`recipe_unlocks.isUnlocked(owner, recipe)`；新增的普通烧制/烟熏/高炉配方会正确读取个人权限。烟熏炉没有独立于熔炉族的额外operation权限。
- 高炉只要求对应配方解锁；制作高炉仍按原配方材料（铁锭、熔炉、平滑石头）准备，未改数量。
- 切石机结果由`recipe_menu_gate`按结果配方的`recipe_unlocks.isUnlocked`检查；解锁切石配方不等于开放其他设备operation权限。
- 未新增任何设备operation权限；炉子仍要求owner记录有效、在线且存活，结果成品取货规则未改。
