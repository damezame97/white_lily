# 第一批研究路线与加工台登记

研究属于玩家；普通合成按实际制作玩家检查权限；研究加工方法登记到具体加工台后，由机器共享使用。打开界面、放入材料和取走成品不会自动传授研究。

## 九个节点

下表所有ID均使用 `white_lily:` 命名空间。前四个发现节点在自己的章节默认可见、首次获得不消耗物品。研究材料与实际制作材料是两份独立消耗。

| 章节/节点ID | 研究前置 | 研究提交 | 绑定配方ID |
| --- | --- | --- | --- |
| 基础草药 / `bitterleaf` | 无，发现苦叶草 | 不消耗 | 无 |
| `bitterleaf_paste` | `bitterleaf` | 苦叶草1＋空白标签1 | `processing/bitterleaf_paste` |
| `yarrow` | 无，发现止血蓍草 | 不消耗 | 无 |
| `yarrow_dressing` | `yarrow` | 止血蓍草1＋空白标签1 | `processing/yarrow_dressing` |
| `calming_flower` | 无，发现安神花 | 不消耗 | 无 |
| `calming_flower_tea` | `calming_flower` | 安神花1＋空白标签1 | `calming_flower_tea` |
| 包扎与敷料 / `coarse_cloth` | 无，发现粗布片 | 不消耗 | 无 |
| `simple_bandage` | `coarse_cloth` | 粗布片1＋细布条1 | `simple_bandage` |
| `clean_fine_bandage` | `simple_bandage`＋`yarrow_dressing` | 简易绷带1＋蓍草敷料1＋空白标签1 | `clean_fine_bandage_beeswax`、`clean_fine_bandage_honey` |

精良绷带只由简易绷带完成后揭示；蓍草敷料是另一个必要研究前置。详情的“查看跨章节前置”跳到已揭示的蓍草研究；如果敷料节点尚未揭示，只允许跳到已可见的止血蓍草发现线索，不泄露隐藏档案或配方。

旧安神花与花茶ID保持原样，退出、死亡、换维度仍保留个人进度。新增节点不会自动授予老玩家；新的获得类根会识别已有背包物品，管理员显式重置后的抑制优先。主动“检查背包”允许重新确认发现，但不代替材料提交。

## 制作配方保持原值

- 麻秆1→植物纤维2：研钵40刻，每批1耐久，基础加工，无需登记。
- 苦叶草3→苦叶药膏2＋药草残渣1：研钵100刻，每批1耐久，需要机器登记。
- 止血蓍草3→蓍草敷料2＋药草残渣1：研钵100刻，每批1耐久，需要机器登记。
- 安神花2＋普通水瓶1→安神花茶1，保留严格水瓶NBT条件。
- 粗布片1＋细布条1→简易绷带2。
- 简易绷带1＋蓍草敷料1＋蜂蜡块1，或将蜂蜡块换为蜂蜜瓶1→洁净的精良绷带1。蜂蜜瓶返玻璃瓶，蜂蜡路线不返瓶。

后三类普通合成必须由实际制作玩家完成相应研究；普通/Shift取出、批量及配方书均沿用服务端门控。成品可以交易和使用，得到成品不代替研究。基础材料与工具继续正常制作。药效、产量、时间及贴图均未修改。

## 机器登记与共享

1. 实际玩家放置加工台时，只将该玩家已学且仍有效的本机加工配方自动登记。创造身份本身不授予研究。命令/结构放置不猜测玩家，只有基础加工。
2. 在加工台点击“登记已学配方”，由服务端从当前操作者个人研究计算新增集合，合并、不覆盖、不消耗，重复登记新增为0。
3. 机器有了登记记录，任何玩家都能放料自动连续加工。不要求研究者在线、在附近或打开界面，也不要求每批点开始。
4. 操作者不因此获得研究，不能把机器知识传给自己或另一台机器。个人研究重置只撤销个人合成和向新机器登记的能力，不撤销旧机器记录。

未登记时显示“此加工台尚未登记该配方”，不推进、不耗料、不损工具。登记后原槽内材料可直接开始。多个匹配配方只在本机有权限的候选中按ID稳定选择，受限配方不挡住可执行配方。

输出预检、堵塞暂停、工具最后1点耐久、输入变化、多人共享和关闭界面继续加工沿用原实现。没有新增燃料、启动按钮、永久授权玩家或在线检查。

## 配方浏览器与本机上下文

打开加工台时，服务端把本机当前有效能力发给该玩家的菜单会话：基础加工配方 + 已登记且研究绑定有效的研究加工配方。客户端只在该 `processing_menu` 会话内使用这份上下文，关闭菜单、换机器、退出或菜单失效后清除。

浏览范围是“个人已解锁配方 + 本机能力”，机器权限精确到配方 ID，不会因为同一产物有已登记加工配方就展示该产物其他未解锁的合成方式。详情状态：

- 已掌握 · 本机可加工：允许填充。
- 本机已登记 · 个人未研究：允许查看和填充，不授予个人研究。
- 本机未登记，请点击“登记已学配方”：个人已学但本机未登记，填充暂不可用。
- 自己未学且本机未登记：不显示完整配方。
- 基础加工：按本机基础能力显示和填充。

新增登记后，所有正在查看同一机器的玩家立即收到新上下文并刷新。服务端填充入口只对加工台使用机器权限，不全局放开个人 `isUnlocked` 或研究判定。

## 熔炉系列

熔炉、高炉、烟熏炉继续由机器 owner 的配方权限决定是否烧制；已经烧好的成品对所有正常打开菜单的玩家开放，普通点击和 Shift 都能取走，不检查取货者是否 owner、是否解锁该烧制配方或是否完成研究。owner 离线只会停止后续烧制，不会锁住已有成品。酿造台、Vinery、铁砧等其他设备本轮不变。

## 保存、拆除与旧机器

方块实体NBT的 `RegisteredRecipes` 保存稳定配方ID集合；服务器重启或区块重新加载后保留。无效字符串安全忽略；已删除/错误类型的配方不能执行，不将旧ID映射成其他方法。加工配方仍存在且绑定相同研究时保留登记，个人状态不参与机器后续执行。

拆除掉落普通全新加工台，不把记录或库存NBT写入方块物品。八槽物品按原方块移除路径分别掉落一次。重新放置只读取新放置者当时研究。加工台物品拒绝导入BlockEntityTag，不能通过带旧机器NBT的物品恢复知识或复制库存；未改其他方块物品行为。

旧机器没有登记字段时，库存和已有进度数据仍保留，基础加工继续；受限加工等待有研究的玩家点击登记。登记后验证当前配方、工具和指纹，相同者继续；指纹不兼容时安全重新开始，不凭旧进度直接产出。

## 安全与数据扩展

登记使用原版菜单按钮请求，只带当前菜单ID和按钮ID，不接收远程坐标或客户端解锁列表。服务端检查真实当前菜单、方块实体身份、距离及操作ID，并以10刻冷却抑制连点。研究、登记和完成都在服务端线程处理。

配置：`data/white_lily/research/handbook.json`。`prerequisites`为必要前置；可选 `reveal_after`为揭示触发前置，必须来自必要前置。未指定时沿用任一直接前置完成即可揭示的旧规则。

研究加工JSON新增 `"research":"white_lily:节点ID"`，同时节点 `recipes` 绑定该加工配方ID；二者不一致时拒绝授予登记。基础加工没有research字段。JSON和配方网络同步都包含该字段。手册完成后读取真实配方显示工具、耐久、时间、副产物；普通合成不显示虚构研钵或耗时。

获取手册：`/give @s white_lily:investigation_handbook`。生产客户端与服务端需一起更新本轮JAR，研究协议版本为3。
