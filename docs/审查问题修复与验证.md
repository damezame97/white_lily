## 相邻路径额外发现并修复

1. Forge的MobEffectEvent.Added在原版合并效果前触发。直接记录传入的短持续时间会错误截断原版仍保留的长效果/无限效果。现在使用副本模拟原版合并，记录合并后的有效持续时间。
2. LivingDamageEvent发生在真正扣血之前。渗血重评可能读到旧满血值，将刚移除的“体况良好”又补回。现在保留待扣血标记，并在对应玩家刻核对实际生命结果。
3. Forge取消AnvilUpdateEvent会直接退出createResult，不清理旧结果。现在拒绝戒指维修时同时清空当前实际铁砧的旧输出与费用，防止先改名再放第二件物品留下旧结果。
4. 不允许维修的物品声明本身不能可靠代替铁砧合并限制，现已显式堵住两枚戒指合并维修路径。
5. 其他模组通过Applicable明确拒绝感染失明时，原逻辑仍会留下发作计时并在60刻后发放清明。现在只有真正施加成功才保留事件时钟，拒绝时回滚，不制造清明。

不能仅凭旧的isRepairable=false断定用户原来左槽单件改名失败的原因：原版单件改名不直接检查该标志。新增明确处理路径已经通过服务端真实AnvilMenu自动测试；用户原启动器客户端现场仍需人工确认。
