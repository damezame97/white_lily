# 可选冲突选择器测试数据包

仅测试用，不在正式JAR内、不自动安装、不自动解锁、不替换原有配方。建议在自己的测试世界使用。本助手未进入游戏验证。

## 安装

把 `white_lily_conflict_test.zip` 放入你自行选择的测试世界的 `datapacks` 文件夹，然后执行 `/reload`。需要本次新JAR和管理权限。服务端由管理员安装；不要把zip当成模组放进mods。

明确授予自己的四条测试配方（作弊浏览“显示所有”不能代替这些权限）：

```mcfunction
/recipeunlock grant @s white_lily_conflict_test:stick_a
/recipeunlock grant @s white_lily_conflict_test:stick_b
/recipeunlock grant @s white_lily_conflict_test:water_a
/recipeunlock grant @s white_lily_conflict_test:water_b
```

## 案例1：数量、切换、Shift与浏览器填充

- 一根原版木棍：A产出1圆石；B产出2泥土。两个无序配方材料完全一样。
- 在背包2×2或工作台3×3放4根木棍同一格，点击结果下方按钮，分别选择A/B。选择时不扣木棍。
- 选择B后Shift应产出8泥土，不能掺入圆石；普通取出/数字键也应对应选择。
- 在自制配方浏览器查看泥土的这个测试配方，点击它的＋，成功返回合成界面后结果必须是2泥土，不能是默认圆石。

## 案例2：余料必须跟随选择

- 材料：1张原版纸＋1普通水瓶（不是喷溅/滞留/其他药水）。
- A：1绿宝石，不返瓶；B：2钻石，返还1玻璃瓶。B复用现有显字处方的返瓶序列化器，不新增正式玩法代码或配方。
- 先选A再取出，再重新摆料选B取出，核对两次的产物/数量和玻璃瓶。选择本身不能发瓶、扣料或直接发产物。

## 界面与权限验收

- 弹窗完全盖住右侧列表时，底层图标/tooltip/搜索/收藏/分页不能响应；弹窗外点击只关闭，Esc优先关闭弹窗。
- 悬停材料、成品、候选空白分别检查物品说明及ID/来源/返还说明；不同GUI缩放和小窗口下仍能关闭、滚动与准确选中。
- 若额外安装JEI，另测其填充是否使用原版配方书转移链路；当前仓库未安装JEI，不宣称已验证JEI专有传输协议。
- 可以只先授予stick_b，不授予stick_a：仍应显示可做的B，而不是因为A锁定而空结果。另一玩家不授予任何测试权限时不能借选择器制作。

测试完可移除这份zip并`/reload`，这些独立namespace测试配方即不再存在；不需要清理玩家存档。源JSON保留在同名目录，便于自行调整测试，不打进游戏资源。
