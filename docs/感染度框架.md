# 感染度基础框架

## 范围与现有系统核对

本次只加入感染持久数据、感染抗性、来源登记和两条增长公式、配置、最小同步、扩展接口与管理命令。没有新增物品、症状、疾病、随机症状池、感染分档惩罚、意志公式或 HUD；正式来源表和症状表均为空，因此感染为 0 的玩家不会凭空感染。

已核对当前作者代码：

| 实际注册 ID | 当前含义与用途 | 本次处理 |
|---|---|---|
| `white_lily:san` | SAN，存在档位初始化、崩溃与融毁规则 | 保留，不改规则 |
| `white_lily:willpower_strength` | 语言名“意志坚韧”，默认 0.05，当前未找到独立症状强度消费公式 | 不修改、不建立假定对应关系 |
| `white_lily:steadfast_in_spirit` | 作者新版本已移除的旧键，现有测试要求不再存在 | 不重新注册，不把它当成 SAN 或意志坚韧 |
| `white_lily:stamina` | 现有耐力值，参与 Happy_mode 恢复消耗；SAN 崩溃的修饰符会使其降低 10 | 读取有效值，不注册第二套，不改变原规则 |

“意志坚定值”的未来含义与对应属性仍待设计。本次未改 Mixin、SAN、饥饿、耐力消耗或 Happy_mode 代码。

## 注册与保存

- 感染抗性在原有 `attribute/attributes.java` 的统一注册表中新增 `INFECTION_RESISTANCE`：`white_lily:infection_resistance`，默认 0.0、有效范围 0.0～0.8、可同步，自动添加到玩家；中英文名称与说明齐全。
- 感染状态通过原有 `capability/player_variables.java` 挂载，Capability 标识为 `white_lily:infection_state`。
- `capability/infection_state.java` 保存 `units`（0～3000）与 `passive_ticks`（0～1199，已完成的周期刻数）。感染显示值为 units/10，周期剩余刻数为 1200−passive_ticks。
- 不保存小数余量、溢出或现实时间戳。缺失字段归零；错误类型和非有限数归零；有限越界值先夹范围再转整数。满 300.0 和感染为零时周期清零。
- 正常退出保留，离线不推进；换维度复制数值、周期和本刻去重标记；死亡重生按配置保留/清除感染，周期始终清零。新玩家拥有独立数据实例。

## 计算

生命比例使用 `getHealth()/getMaxHealth()`，有效上限包含装备和其他修饰；黄心不参与。无效数值暂停自动增长，死亡或死亡动画期间不增长。

| 生命比例 h | M | G（每1200刻） |
|---|---:|---:|
| h > 0.70 | 1.0 | 0.0 |
| 0.40 < h <= 0.70 | 1.2 | 0.5 |
| 0.20 < h <= 0.40 | 1.8 | 1.0 |
| h <= 0.20 | 2.8 | 2.0 |

耐力入口为 `infection_service.stamina(player)`。S<0 时 K=min(2,1−S×0.25)；S>=0 时 K=max(0.5,1−S×0.1)，支持小数。SAN −10 仍参与，K 封顶 2。

`infection_math` 使用十进制 BigDecimal 完成增加量公式，最后 HALF_UP 到十分位整数，每次独立舍入：

```text
外来：B × [1 + (M − 1) × K] × (1 − R)
被动：G × K × (1 − R)
```

耐力只影响外来感染的伤势额外部分。触发概率不受抗性影响。返回的外来实际增加量是经过 300.0 上限截断后真正增加的数值。

已验证例子：生命 6/20、S=−2、R=0.2、B=10，得到 h=0.3、M=1.8、G=1、K=1.5；外来成功增加 17.6，被动一周期增加 1.2。

被动增长只在存活、感染>0、生命<=70%、框架开启且不处于排除的无敌模式时累计。档位变化不重置，结算使用当时的 G/K/R。恢复到70%以上、感染归零或满值清计时；关闭框架和创造/旁观/无敌模式暂停，清空条件仍优先执行。服务端 PlayerTick END 更新对应玩家，不扫描世界；使用服务端全局游戏刻去重，维度切换不额外结算。

## 配置

由 Forge SERVER 配置管理，保存在各世界的 `serverconfig/white_lily-server.toml`：

```toml
[infection]
enabled = true
keepOnDeath = true
```

`enabled` 默认开启，独立于 Happy_mode。关闭时冻结自动增长和来源触发，不清除已有感染；查询、直接管理和治疗入口仍有效。`keepOnDeath` 默认暂定保留感染；设 false 则死亡重生清除感染。两种取值均在重生时清空周期。

## 调试命令

沿用 `/white_lily` 根节点，只有 `infection` 子树要求权限等级 2，不改变旧 tense 命令权限。

```mcfunction
/white_lily infection get @s
/white_lily infection set @s 17.6
/white_lily infection add @s 1.2
/white_lily infection reduce @s 0.5
/white_lily infection clear @s
/white_lily infection simulate @s 1 10
/white_lily infection source @s your_mod:registered_source
```

- `get` 显示感染度、生命百分比、M/G、S/K/R、周期进度和总开关。
- `set/add/reduce/clear` 不套风险公式。set 超过300夹到300、低于0归零；add/reduce只接受非负数。非有限数拒绝。
- `simulate <targets> <probability> <base>` 使用临时调试来源，遵守框架开关、玩家状态和风险公式，不将来源写入正式表。概率范围0～1，base非负。创造模式会拒绝感染来源，因此验证增长请切生存模式。
- `source` 只调用已经正式登记的来源；本次表为空，未知ID会报错。
- `@s/@a/玩家名` 等原版玩家选择器可用，消息使用中英文翻译。

复核指定例子时，可在生存模式设置耐力 −2、感染抗性0.2、实际生命6/20，然后执行 `simulate @s 1 10`。普通 /damage 会受到当前模组全部伤害规则影响，不能直接把指令原始伤害当作最终生命差。

## 后续接入位置

### 新增正式来源

在确定玩法后，于 common setup 登记唯一 ID；在对应的服务端事件发生时调用统一入口。本次没有自动接入食物、绷带、怪物或环境。

```java
infection_sources.register(new infection_sources.Source(sourceId, probability, baseAmount));
infection_service.Result result = infection_service.trySource(player, sourceId);
// result.triggered(), result.actualAdded(), result.after(), result.status()
```

### 治疗与调试

```java
infection_service.query(player);
infection_service.reduce(player, healingAmount);
infection_service.addDirect(player, debugAmount);
infection_service.set(player, desiredValue);
infection_service.clear(player);
```

玩法写入统一走 service，避免直接改 Capability 漏掉周期清理、症状重评和同步。只在服务端写入。

### 症状与意志

`infection_symptoms.register(ruleId, (player, conditions) -> { ... })` 提供简单 Java 回调。当前没有任何登记规则。感染数值变化及登录/重生/维度切换时自动重评；未来生命、SAN或意志变化也可调用 `infection_symptoms.reevaluate(player)`。当前不根据这些变化生成任何假定惩罚。

安全属性工具在 `infection_modifiers`：

```java
infection_modifiers.put(player, ruleId, attribute, desiredAmount, operation);
infection_modifiers.remove(player, ruleId, attribute);
```

修饰符名称为 `white_lily:infection/<规则ResourceLocation>`，UUID 由该名称与属性注册 ID 派生，两者同时匹配才属于感染系统。同一规则同一属性拥有一个可更新的临时修饰符；需要多个操作时使用不同规则 ID。值未变时不拆装；只解除本规则拥有的修饰符，UUID 与其他系统冲突时拒绝覆盖。

感染耐力取值排除所有符合该所有权约定的感染修饰符，然后按原版 ADDITION → MULTIPLY_BASE → MULTIPLY_TOTAL → sanitize 的完整规则重算。不会修改玩家实际属性、不会排除 SAN 修饰符，不靠“最终值减惩罚”近似。

阈值、意志对应关系、症状强度、恢复间隔/SAN惩罚、精神疾病和治疗来源都留待后续确定。

## 同步

此前项目没有自有通用数据通道，只有原版属性/消息同步及 ISS 魔力包。因此新增最小 `white_lily:infection` SimpleChannel，只注册 PLAY_TO_CLIENT 感染快照。客户端不提供感染写入包；服务端代码从不接收客户端感染值。

登录、重生、换维度强制同步；感染数值变化时同步一次。周期计时每刻只在服务端更新，不每刻发包；快照中的进度仅代表该次同步时刻，不能直接作为未来HUD的实时倒计时。管理命令始终查询服务端实时周期。客户端通过自身 Capability 读取感染显示值，本次未添加 HUD 或持续聊天/快捷栏提示。
