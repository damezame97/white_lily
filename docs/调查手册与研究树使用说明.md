# 调查手册与研究树（第一版）

> 本文保留第一版历史说明。当前已扩展为9节点、两个章节，并加入加工台登记机制；最终规则与用法见[基础研究路线与加工台登记说明](基础研究路线与加工台登记说明.md)及WORK_REPORT第13节。下文“本轮只开放安神花”不代表当前范围。

本轮只开放“草药与医疗 → 基础草药”的安神花路线。植物自然生成继续暂停；没有研究桌、团队共享、随机失败或额外药效。

## 玩家操作

1. 调查手册可由 **书×1＋空白标签×1＋炭粉×1** 无序合成，最大堆叠1；也在歧途“生计”中药草布包之后展示。
2. 手持右键，或打开生存/创造背包后点击屏幕左上角的手册按钮。按钮不要求背包里有实体手册。从按钮进入后关闭会返回原背包；手持进入后关闭返回游戏。
3. 新玩家最初只能看见灰色“发现安神花”。安神花实际进入自己背包后，至多约1秒完成发现，不消耗花；打开手册时也会立即检查已持有物品。浏览创造栏图标、附近掉落物和箱中物品均不算发现。
4. 根节点完成只揭示下一层“研究安神花茶”。选中花茶，备齐 **安神花×1＋空白标签×1**，点击“完成研究”。两种材料分散在不同格子也可以；创造模式同样扣除研究材料。
5. 完成后才能查看和制作既有 **安神花×2＋普通水瓶×1 → 安神花茶×1** 无序配方。研究消耗与制作消耗分开计算，治疗/其他药水、喷溅和滞留水瓶均不能替代普通水瓶。
6. 进度属于玩家永久记录。手册丢失、重新制作或赠送，均不转移/撤销个人进度；收到他人的花茶可以饮用，不能代替研究。

树区域空白处可拖动，滚轮缩放范围为0.5～2.0；“恢复视图”重新居中。侧栏和详情分别支持滚动，滚轮不穿透到研究树。已完成勾、锁、可研究加号和选中边框分别显示。

## 获取与测试命令

```mcfunction
/give @s white_lily:investigation_handbook
/give @s white_lily:calming_flower 3
/give @s white_lily:blank_label
/give @s minecraft:potion{Potion:"minecraft:water"}
/give @s minecraft:book
/give @s white_lily:charcoal_powder
```

要验证真正初始状态，使用没有研究记录的新测试玩家。`/clear` 只清物品，不重置永久研究。不要为了测试删除既有玩家数据。

未研究时先手动摆好花茶材料，2×2和3×3结果应为空；即便旧配方书曾记录该配方也不应填充制作。研究完成后立即开放，不要求重新登录。普通水瓶正常不堆叠，配方书“全部填充”遵守其原堆叠上限，不扩张水瓶堆叠数。

## 当前档案的客观效果

- 安神花：使用前SAN≥5000恢复10，低于5000恢复5；反胃Ⅰ20秒；不能用骨粉复制。
- 安神花茶：饮用前SAN≥5000恢复30，低于5000恢复15；反胃Ⅰ10秒；饮用后返还玻璃瓶。

以上复用当前医疗物品实现，本轮没有改SAN、感染、治疗或种植数值。

### 新节点示例（文档示例，不会加载）

向已有配置的 `nodes` 数组增加节点，或在 `data/<命名空间>/research/` 增加文件；新文件必须提供 `categories` 和 `nodes` 数组，复用已有栏目时前者可以为空数组。补齐所引用的中英文翻译键。示例只使用现有材料，不会自动增加配方门槛：

```json
{
  "id": "white_lily:sample_note",
  "category": "white_lily:herbs_medical",
  "chapter": "white_lily:basic_herbs",
  "icon": "white_lily:blank_label",
  "name": "research.white_lily.sample.name",
  "intro": "research.white_lily.sample.intro",
  "hint": "research.white_lily.sample.hint",
  "x": 200, "y": 0,
  "prerequisites": ["white_lily:calming_flower_tea"],
  "root_visible": false,
  "condition": "submit",
  "materials": [{"item": "white_lily:blank_label", "count": 1}],
  "recipes": [],
  "archive": ["research.white_lily.sample.archive.1"]
}
```

`condition: obtain` 则使用 `target` 指定首次获得的物品。`prerequisites` 支持多个稳定ID：任一直接前置完成可以揭示，所有前置完成后才允许研究。坐标、文案变化不会撤销记录；暂时不存在的旧节点记录仍保留。

服务端校验重复ID、前置缺失/循环、物品、数量、栏目章节及配方引用，错误会记录具体文件/节点/配方，拒绝损坏配置或相应研究。当前配方展示器正式支持无序合成（含本轮研究型配方），不把不支持的配方假装成无序合成。

以后给新普通无序配方绑定研究，需要在节点 `recipes` 中填真实配方ID，将对应配方类型设为 `white_lily:research_crafting`，并避免普通进度提前解锁。加工配方也可在结构中绑定ID，但发布前需补对应展示格式和明确机器的玩家授权归属；本轮没有限制任何加工台配方。

条件扩展在 `research_catalog` 的解析/索引和 `research_service` 的完成入口接入，不在Screen中写物品判断。观察、使用或辨识处方尚未实现。

## 同步、权限与适配边界

- 服务端能力以稳定节点ID保存，死亡与非死亡Clone均正确读取旧能力并复制；登录、重生、换维度和数据重载重新同步及刷新配方书/结果槽。
- 初始/打开/重载发送已裁剪的可见快照；后续发送变化节点、移除ID和配方权限差分。手册打开时每10刻检查展示变化，首次获得目标每20刻检查自己的背包索引；不每刻广播全树。
- 未发现节点不发送档案/配方，未揭示的深层节点连ID、名称、图标、连线都不下发。完整配置留在服务端。模组资源、原版配方同步或外部工具仍可被技术用户检查，不能宣称配方绝对保密。
- 独立研究Mixin限制真实合成匹配、结果取出、Shift转移、配方书授予/初始化和NBT水瓶自动填充；没有修改作者原有Mixin实现或全局药水规则。
- 当前依赖没有JEI/REI；没有安装新查看模组，也没有宣称已验证其兼容。将来增加查看工具时需要专门处理玩家解锁显示及刷新。
- UI及真实多人联机的完成情况以交接报告为准；GameTest中的两玩家隔离并不等于两台客户端联机实测。
